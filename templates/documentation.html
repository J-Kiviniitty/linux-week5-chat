CI/CD Pipeline

Every push and pull request executes Ruff and Pytest. Deployment runs only after successful tests. 

Push / Pull Request
        ↓
Ruff
        ↓
Pytest
        ↓
Deploy (main branch only)
        ↓
Health Check

Deployment copies the code to the server, installs dependencies, updates the Nginx and systemd configuration, restarts only the Week 5 chat application service, and verifies deployment through the /viikko5/health endpoint.

Users, Permissions and Secrets

  • Linux application user: chatapp
  • Deployment user: ubuntu
  • MariaDB database: chatapp
  • MariaDB user: chatapp
  • Ollama listens only on localhost.
  • Gunicorn listens through a Unix socket.
  • Secrets are stored in /etc/chatapp/chatapp.env.
  • GitHub Actions uses repository secrets for deployment.

Nginx Integration

The Week 5 application was added through an Nginx snippet under the path /viikko5/. Existing applications continue to function without modification.

Model Choice

Server resources:

  • RAM: 7.6 GiB
  • CPU: 4 vCPUs
  • Disk available: 74 GiB

The selected local language model is qwen2.5:0.5b. The model fits comfortably within the available memory and provides fast response times on the virtual server.

Week 4 Replication

The Week 5 chat database is not replicated to Server B. Week 4 replication was implemented only for the visitor counter database. The chat application stores its own conversation history in a dedicated MariaDB database on Server A.

Problem Solved

The deployment pipeline initially failed because the Python virtual environment had been copied to a different directory. The Gunicorn executables still contained references to the original location. The problem was solved by rebuilding the virtual environment in the final deployment directory and reinstalling dependencies.
